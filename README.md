# nafas chat bot 💬

یک **چت‌بات گفت‌وگومحور** به زبان فارسی. هیچ منوی دکمه‌ای، هیچ وب‌هوکی، هیچ دیتابیسی — فقط:
حرفِ کاربر → مدل → جواب.

پروژه یک بک‌اند Next.js است که روی Vercel دیپلوی می‌شود و از دو راه در دسترس است:

- **تلگرام** — ربات، پیام را می‌خواند و جواب می‌دهد.
- **HTTP** — `POST /api/chat` برای هر اپ یا صفحه‌ای که می‌خواهد چت کند (یک صفحهٔ چتِ ساده هم روی `/` هست).

> نسخهٔ قبلی این مخزن یک واسطِ وب‌هوک برای کلینیک بود. همهٔ آن امکانات حذف شده‌اند؛
> الان فقط گفت‌وگو باقی مانده است.

---

## مسیرِ یک پیام

```
کاربر می‌نویسد
      │
      ▼
 /api/telegram/webhook  ← یا →  POST /api/chat
      │
      ▼
 handleChat()               lib/bot/index.ts
      │  پرامپت سیستم + حافظهٔ گفت‌وگو
      ▼
 OpenRouter (زنجیرهٔ مدل‌های :free)   lib/openrouter/client.ts
      │  اولین مدلی که جواب بدهد برنده است
      ▼
 جواب فارسی + ذخیره در حافظه
```

حافظهٔ گفت‌وگو در حافظهٔ همان پروسه نگه داشته می‌شود (چند پیامِ آخر، با TTL) —
بدون دیتابیس. اگر کاربرِ هم‌زمانِ زیادی داشتی، همین یک فایل
(`lib/bot/session.ts`) را به Upstash/Redis وصل کن.

## هویت و تقویم

**«تو کی هستی؟»** همیشه یک جواب دارد: «من نفَس هستم، دستیار هوشمند کلینیک زیبایی نفس.»
این جواب در `lib/bot/identity.ts` با کد داده می‌شود، نه با پرامپت — چون مدلِ کوچکِ مجانی
گاهی خودش را «یک مدل زبانی» معرفی می‌کند. اسم کلینیک با `CLINIC_NAME` عوض می‌شود.

**تاریخ** سه لایه دارد و همه با `date-fns` کار می‌کنند:

| لایه | فایل | کار |
| --- | --- | --- |
| خواندنِ تاریخ از جمله | `lib/dates/parse.ts` | «۱۲ مرداد ۱۴۰۳»، «1403/05/12»، «2024-08-15»، «15 August 2024»، «امروز»، «پنجشنبه»، «عید»، «۱۴۰۳» |
| محاسبه | `lib/dates/engine.ts` | تبدیل، فاصلهٔ دو تاریخ، رنج روزها، جمع و تفریق زمان، طول ماه، سال کبیسه |
| تصمیم | `lib/dates/intent.ts` | کدام عملیات خواسته شده — و اینکه آیا اصلاً سؤالِ تاریخ است یا نه |

سه تقویم: **شمسی** (`date-fns-jalali`)، **میلادی** (`date-fns`)، **قمری** (`Intl` با
`islamic-umalqura`).

```
«بین 1403/01/01 و 1403/01/10 چند روزه»
   → parse: دو تاریخ پیدا شد
   → engine: differenceInCalendarDays = 9
   → مدل: فقط جمله را می‌نویسد، عدد را دست نمی‌زند
   → اگر عدد را عوض کرد، جوابِ محاسبه‌شده جایگزین می‌شود
```

چهار نکته که عمداً این‌طور طراحی شده‌اند:

1. **محاسبات با کد است، نه با مدل.** مدلِ کوچک تاریخ را از حفظ می‌سازد؛ پس عدد را ما حساب
   می‌کنیم و مدل فقط جمله‌بندی می‌کند. اگر مدل عدد را خراب کند، `summary` محاسبه‌شده
   جایگزین می‌شود.
2. **هرگز خالی نمی‌ماند.** اگر همهٔ مدل‌ها از کار بیفتند، جوابِ تاریخ هنوز درست است.
3. **ساعت از سرور، در منطقهٔ درست.** سرور UTC است و `TIME_ZONE=Asia/Tehran`. یک لحظه در
   UTC می‌شود ۱۴۰۵/۰۸/۱۸ و در تهران ۱۴۰۵/۰۸/۱۹ — پس `@date-fns/tz` لازم است.
4. **جملهٔ معمولی را اشتباه نمی‌گیرد.** «دیروز خیلی خسته بودم» سؤالِ تاریخ نیست؛ یک
   کلمهٔ نسبی به‌تنهایی کافی نیست، باید یا تاریخِ صریح باشد یا کلمهٔ پرسشیِ تاریخ.

**دربارهٔ `date-fns-jalali`:** این یک فورکِ کاملِ date-fns است که کل API را روی تقویم
جلالی اجرا می‌کند. دو چیزی که اندازه‌گیری شد و در کد هم نوشته شده:

- ماه/سال را **حتماً** با نسخهٔ جلالی حساب کن: `addMonths(1403/01/31, +6)` در date-fns
  می‌شود `1403/07/28` (چون شش ماهِ *میلادی* جلو می‌رود) و در نسخهٔ جلالی `1403/07/30` ✓
- تبدیل‌ها روی **۴۸۶۷ روزِ نمونه در ۴۰ سال** با `jalaali-js` مقایسه شد: صفر اختلاف.
  `Intl` با `ca-persian` هم همان ۱۴۰۵/۰۸/۱۸ را می‌دهد.

قاعدهٔ کبیسه، الگوریتمِ حسابیِ ۳۳‌ساله است (مثل خودِ jalaali-js)؛ در برخی سال‌ها ممکن است
یک روز با تقویمِ نجومیِ رسمی اختلاف داشته باشد.

## ذخیرهٔ تنظیمات در دیتابیس

هر چتِ تلگرام یک `session_id` دارد که در Postgres ذخیره می‌شود: کلید، شناسهٔ چتِ تلگرام
است و مقدار، همان session.

| فایل | کار |
| --- | --- |
| `lib/db/client.ts` | اتصال به Neon با درایور HTTP خودِ Neon؛ تعمیرِ رشتهٔ اتصال؛ timeout |
| `lib/db/schema.ts` | جدول `chat_sessions` — idempotent، پس هر بار می‌تواند اجرا شود |
| `lib/db/chat-sessions.ts` | upsertِ «کلید → session» + کش در حافظهٔ پروسه |

```sql
create table if not exists chat_sessions (
  telegram_chat_id bigint      primary key,   -- همان key که خواستی
  session_id       text        not null,      -- همان session
  phone            text,                      -- موبایل ایران، به شکل 09121234567
  created_at       timestamptz not null default now(),
  updated_at       timestamptz not null default now(),
  last_seen_at     timestamptz not null default now()
);
```

جدول‌هایی که **قبل از** ستون `phone` ساخته شده‌اند خودکار عریض می‌شوند
(`alter table … add column if not exists`)، پس نیازی به migration دستی نیست.

سه تصمیم:

1. **دیتابیس یک وابستگی نیست، یک افزونه است.** اگر `DATABASE_URL` خالی باشد یا Neon
   نرسد، بات دقیقاً مثل قبل کار می‌کند و session را از `tg-<chatId>` می‌سازد. پیامِ کاربر
   هیچ‌وقت به خاطر دیتابیس از دست نمی‌رود.
2. **یک upsert، نه select-بعد-insert.** با `(xmax = 0) as inserted` در همان `RETURNING`
   می‌فهمیم چت تازه بوده یا نه — بدون کوئری دوم.
3. **کش در حافظهٔ پروسه.** session یک چت هیچ‌وقت عوض نمی‌شود، پس بعد از اولین پیام، آن
   چت دیگر به دیتابیس دست نمی‌زند. عمداً شمارندهٔ پیام نگذاشتم: به‌روزش نیازمندِ یک write
   روی هر پیام بود و روی serverless آن write تضمین‌شده نیست — ستونی که گاهی دروغ می‌گوید
   از نبودنش بدتر است.

`newSessionId()` در `lib/db/chat-sessions.ts` **تنها** جایی است که session ساخته می‌شود.
وقتی گفتی session از کجا باید بیاید، فقط همان یک تابع عوض می‌شود.

## شمارهٔ تلفن

تا وقتی شمارهٔ موبایل یک چت در دیتابیس نباشد، **هیچ پیامی جواب داده نمی‌شود**. بات یک
بار شماره را می‌خواهد و بعد همه‌چیز عادی است.

شماره از خودِ تلگرام می‌آید: یک دکمهٔ `request_contact` زیر کادر پیام می‌نشیند و کاربر با
یک ضربه شمارهٔ حساب تلگرامش را می‌فرستد (`message.contact`)، نه چیزی که تایپ کرده باشد.
اگر دکمه را نزند، می‌تواند شماره را تایپ کند.

| فایل | کار |
| --- | --- |
| `lib/phone.ts` | خواندن و نرمال‌سازی شماره؛ تنها جایی که قاعدهٔ «فقط ایران» هست |
| `lib/telegram/phone-gate.ts` | خودِ gate: پرسیدن، گرفتن، رد کردن، تأیید |
| `lib/telegram/api.ts` | `contactKeyboard()` و `removeKeyboard()` |

قاعدهٔ ذخیره: **`09XXXXXXXXX` — یازده رقم، بدون کد کشور.** همهٔ شکل‌ها به همین یک شکل
تبدیل می‌شوند:

| ورودی | ذخیره می‌شود |
| --- | --- |
| `۰۹۱۲۱۲۳۴۵۶۷` (رقم فارسی) | `09121234567` |
| `+989121234567` / `00989121234567` | `09121234567` |
| `989121234567` | `09121234567` |
| `9121234567` (بدون صفر) | `09121234567` |
| `0912-123-4567` / `(0912) 123 4567` | `09121234567` |
| `+14155552671` / `02112345678` | رد می‌شود |

سه نکته:

1. **`/start` هم پشت gate است** — خوش‌آمدگویی قبل از شماره داده نمی‌شود. تنها استثنا
   `/id` است: چیزی ذخیره نمی‌کند و تنها راهِ فهمیدنِ chat id برای
   `TELEGRAM_ALLOWED_CHAT_IDS` است؛ بستنش یعنی بن‌بست.
2. **در گروه‌ها دکمهٔ اشتراک شماره وجود ندارد** (محدودیت خودِ تلگرام)، پس بات در گروه
   شماره را به‌صورت متنی می‌خواهد.
3. **بدون دیتابیس، gate کنار می‌رود.** جایی برای ذخیرهٔ شماره نیست و پرسیدنِ بی‌پایان
   یعنی بات برای همه از کار افتاده — پس مثل قبل جواب می‌دهد. `PHONE_GATE=off` هم gate را
   خاموش می‌کند در حالی که ذخیره‌سازی سر جایش می‌ماند.

```bash
npm run db:check                       # اتصال + ساخت جدول + رفت‌وبرگشتِ واقعی
curl -s https://<your-app>/api/health?db=1
```

## انتخابِ خودکارِ مدل

بات مدل را دستی انتخاب نمی‌کند؛ هر بار **بهترین مدلِ مجانیِ در دسترس** را از فهرست
زندهٔ OpenRouter برمی‌دارد. سه سیگنال دارد:

| سیگنال | از کجا | چرا |
| --- | --- | --- |
| **کیفیت** | جدولِ دستیِ `QUALITY_TIERS` در `lib/openrouter/ranking.ts` | API اوپن‌روتر هیچ نمرهٔ هوشی نمی‌دهد، پس قضاوتِ ما باید یک‌جایی نوشته شود |
| **سرعت** | اندازه‌گیریِ واقعیِ خودِ بات (`lib/openrouter/stats.ts`) | API هیچ latency هم نمی‌دهد؛ تنها عددِ واقعی، زمانِ جواب‌های خودمان است |
| **سلامتی** | cooldown بعد از خطا | مدلی که ۴۲۹ می‌دهد باید برود عقبِ صف، نه اینکه حذف شود |

```
فهرست زندهٔ :free → فیلتر زمینه → نمرهٔ کیفیت + سرعت − cooldown → N مدلِ اول
```

سه قانون که نگهشان داشته‌ام:

1. **هرگز خالی نمی‌شود.** اگر فهرست زنده گرفته نشد، به `OPENROUTER_MODELS` برمی‌گردد.
   باتِ بی‌حرف بهتر از باتِ کم‌حرف نیست.
2. **حذف نمی‌کند، فقط عقب می‌فرستد.** مدلِ خطاداد بعد از `MODEL_COOLDOWN_MS` برمی‌گردد.
3. **همیشه کاوش می‌کند.** یک جایِ استخر به مدلی که هنوز زمانش را نگرفته‌ایم می‌رسد،
   وگرنه اولین مدلی که جواب داد تا ابد «سریع‌ترین» می‌ماند.

**یک نکتهٔ صادقانه:** «سریع‌ترین» و «باهوش‌ترین» معمولاً دو مدلِ متفاوت‌اند
(مدل‌های مجانیِ باهوش کندترند). پس وزنِ سرعت عمداً کمتر از فاصلهٔ بین رده‌های کیفیت است:
کیفیت رده را تعیین می‌کند و سرعت فقط بین مدل‌های هم‌رده تصمیم می‌گیرد.
اگر اولویتت سرعت است، `QUALITY_TIERS` را ویرایش کن یا `MODEL_SELECTION=fixed` بگذار.

```bash
npm run models      # رتبه‌بندیِ زنده + زنجیره‌ای که بات الان راه می‌رود
curl -s https://<your-app>/api/health   # همان، به‌همراهِ سرعت‌های اندازه‌گیری‌شده
```

## راه‌اندازی

```bash
npm install
cp .env.example .env.local     # OPENROUTER_API_KEY را بگذار
npm run dev                    # http://localhost:3000
```

برای تلگرام:

```bash
# ۱) از @BotFather توکن بگیر و در TELEGRAM_BOT_TOKEN بگذار
# ۲) آدرس https خودِ پروژه را در PUBLIC_APP_URL بگذار
npm run telegram:setup         # وب‌هوک را ثبت می‌کند
```

بعد از هر استارتِ سرور، ثبت وب‌هوک خودکار انجام می‌شود (`instrumentation.ts`)؛
`npm run telegram:setup` فقط برای وقتی است که می‌خواهی دستی انجامش بدهی.

## بررسی

```bash
npm run check        # typecheck + خودتستی
```

`npm run selftest` کاملاً **آفلاین** است: OpenRouter و تلگرام را جعل می‌کند و مسیر واقعی
کد را از ابتدا تا انتها می‌زند — از `handleChat` و حافظهٔ گفت‌وگو تا هر دو route
و هندلر تلگرام. نه کلید می‌خواهد نه شبکه.

## متغیرهای محیطی

فهرست کامل با توضیح در [`.env.example`](.env.example). مهم‌ترین‌ها:

| متغیر | چرا |
| --- | --- |
| `OPENROUTER_API_KEY` | بدون آن بات فکر نمی‌کند |
| `MODEL_SELECTION` | `auto` (پیش‌فرض) از فهرست زنده انتخاب می‌کند؛ `fixed` فقط `OPENROUTER_MODELS` |
| `MODEL_POOL_SIZE` | چند مدل به‌ترتیب امتحان شود (پیش‌فرض ۴) |
| `OPENROUTER_MODELS` | زنجیرهٔ پشتیبان + مدل‌های مورد اعتمادِ تو؛ `npm run models` رتبه‌بندی زنده را نشان می‌دهد |
| `BOT_NAME` | اسمی که بات برای خودش به کار می‌برد |
| `CLINIC_NAME` | در جوابِ «تو کی هستی؟» گفته می‌شود |
| `TIME_ZONE` | منطقهٔ زمانی برای «الان ساعت چنده» (پیش‌فرض `Asia/Tehran`) |
| `DATE_ASSISTANT` | `false` لایهٔ تقویم را کامل خاموش می‌کند |
| `DATABASE_URL` | اتصال Postgres/Neon؛ خالی = بدون دیتابیس |
| `PHONE_GATE` | `off` = شماره نخواه (پیش‌فرض: روشن، ولی فقط وقتی دیتابیس هست) |
| `HISTORY_MESSAGES` | چند پیامِ آخر به‌عنوان زمینه به مدل برود |
| `BOT_API_KEY` | محافظت از `/api/chat` |
| `ALLOWED_ORIGINS` | چه دامنه‌هایی از مرورگر اجازهٔ صدا زدن دارند |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_WEBHOOK_SECRET` / `PUBLIC_APP_URL` | وصل شدن به تلگرام |
| `TELEGRAM_ALLOWED_CHAT_IDS` | فقط این چت‌ها بتوانند با بات حرف بزنند |
