# تست واقعیِ بدون تغییر اطلاعات

Workflow: **Live read-only checks** در `.github/workflows/live-readonly.yml`.

## آماده‌سازی امن

1. این تغییرات باید با PR بررسی شوند. برای ظاهر شدن دکمهٔ اجرای دستی، workflow باید ابتدا روی شاخهٔ پیش‌فرض (`main`) باشد. ادغام خودکار انجام نمی‌شود.
2. در GitHub مخزن، مسیر **Settings → Environments** یک environment با نام `live-readonly` بسازید. در صورت پشتیبانی مخزن، required reviewers و محدودیت شاخهٔ `main` را فعال کنید تا فقط کد بررسی‌شده به secrets دسترسی داشته باشد.
3. در بخش **Environment secrets** همین environment این چهار مقدار را وارد کنید:

| نام Secret | مقدار |
| --- | --- |
| `WEBHOOK_BASE_URL` | مبدأ HTTPS سرویس کلینیک، بدون مسیر؛ مثل `https://nafasbeautyclinic.ir` |
| `WEBHOOK_USERNAME` | نام کاربری سرویس برای Basic Auth |
| `WEBHOOK_PASSWORD` | رمز سرویس |
| `OPENROUTER_API_KEY` | کلید OpenRouter |

از حساب سرویس با کمترین مجوز، ترجیحاً فقط `users.read`، استفاده کنید. هیچ فایل env یا مقداری از secrets را در چت، PR، کد یا لاگ قرار ندهید. برای این workflow به توکن تلگرام یا `BOT_API_KEY` نیازی نیست.

4. پس از ادغام و تنظیم secrets: **Actions → Live read-only checks → Run workflow**، شاخهٔ `main` را انتخاب کنید. در صورت تنظیم بازبین، اجرا نیاز به تأیید دارد.

## چه چیزی اجرا می‌شود؟

- `GET /api/v1/webhooks/users?page=1&perPage=1`: اتصال HTTPS، پذیرش اعتبارنامه و دسترسی خواندن کاربران را با هم بررسی می‌کند. این تست، مجوزهای نوشتن یا همهٔ endpointها را تأیید نمی‌کند.
- همان GET با `search` تصادفی و غیرشخصی: انتظار نتیجهٔ خالی دارد. این فقط بررسی اولیهٔ فیلتر است؛ در صورت خالی بودن کل فهرست، پشتیبانی search ثابت نمی‌شود و تطبیق نام فارسی یا رفع ابهام نام‌های تکراری را هم ثابت نمی‌کند.
- یک POST به endpoint گفت‌وگوی OpenRouter با مدل دقیق `liquid/lfm-3-1.7b:free` و JSON mode، بدون fallback یا retry. پاسخ باید JSON با `ok: true` باشد. هیچ دادهٔ کلینیک به مدل ارسال نمی‌شود. این یک فراخوانی واقعی است و محدودیت نرخ/سهمیهٔ OpenRouter اعمال می‌شود.

هیچ POST/PATCH/DELETE به کلینیک ارسال نمی‌شود. ساخت، ویرایش، حذف و تغییر گروهی کاربران آزمایش نمی‌شوند. این تست end-to-end ربات یا تلگرام نیست.

## لاگ و خطاها

مخزن عمومی است؛ لاگ‌ها را عمومی فرض کنید. اسکریپت فقط نام ثابت تست، PASS/FAIL، وضعیت HTTP و خطای عمومی چاپ می‌کند؛ رکورد کاربران، نام کاربری، URL سرویس، Authorization، متن پاسخ و متن خام خطا چاپ یا به artifact تبدیل نمی‌شوند. اطلاعات پاسخ فقط در حافظهٔ runner بررسی می‌شوند.

- `401`: اعتبارنامه رد شده؛ `403`: دسترسی رد شده. علت دقیق ممکن است وابسته به سرویس یا پراکسی باشد.
- `429`: محدودیت نرخ یا سهمیه؛ `5xx`: مشکل upstream.
- خطای عمومی شبکه: DNS/TLS/timeout/redirect/JSON نامعتبر؛ جزئیات عمداً مخفی‌اند.
- `unexpected response shape/content`: ساختار پاسخ با شکل‌های `[]`، `{items: []}`، `{rows: []}` یا `{data: []}` سازگار نیست، جستجوی تصادفی نتیجه داده، یا مدل JSON مورد انتظار را برنگردانده است. پاسخ خام را منتشر نکنید.

اتصال runner گیت‌هاب به سرویس کلینیک از قبل تضمین نشده است. تست mock فقط ایمنی و منطق اسکریپت را تأیید می‌کند، نه اتصال واقعی را.

## اجرا روی سیستم خودتان (اختیاری، Node 22)

متغیرها را در فایل محلی و gitignored با نام `.env.local` نگه دارید:

```bash
node --env-file=.env.local scripts/live-readonly.mjs
```

برای تست‌های آفلاین بدون secrets و بدون شبکه:

```bash
node --test scripts/live-readonly.test.mjs
```
